# 前端与申请决策体验审查 · 2026-09-16

## 目标与架构

本轮按用户确认的“申请决策平台”方向实施：把项目发现、筛选、对比、时间状态与官方证据连成同一条决策路径。沿用现有 Atlas 的纸色、朱红与玉绿品牌，不重写成熟的目录查询和分页架构。

现有架构是 Next.js 服务端页面读取发布投影，目录筛选保存在 URL 中；收藏工作区通过比较 API 按最多四条一组加载数据。发布投影负责剔除不可公开或过期的动态事实，UI 负责解释未知、复核期限和申请状态。新增功能复用已有 `FactValue`、`Badge`、日期模型和六语言文案，不新增运行时依赖。

本次所读规范包括项目 AGENTS.md、frontend-design、brainstorming，以及本地 Next.js 的 Server and Client Components、page 和 connection 文档。框架执行版本已由主任务升级至 16.3.5。

## 产品与实现取舍

- **复核期不是有效期承诺。** `reviewAfter` 是下一次应检查证据的日期。即使仍在周期内，网站也不会把“资料已核验”说成“正在接受申请”。
- **详情使用请求时渲染。** 这会增加相较纯静态页面的服务端渲染工作，但避免长达一天的错误时间状态。数据发布仓库与来源采集逻辑仍独立管理，不能把页面请求当成重新访问官网核查。
- **保留参考证据，不作为当前价格。** 未重新确认的费用不能参与申请决策中的当前费用展示；官方原文仍可在来源区查看。
- **URL 筛选与渐进增强保持不变。** 新增快捷入口使用普通链接，表单仍使用 GET，可复制、可刷新，也不需要额外客户端状态。
- **响应式信息层次。** 时效面板宽屏双栏，窄屏单栏；语义化 heading、dl、time 和文字状态让用户不用依赖颜色辨认可信度。
- **首页和城市详情范围。** 已审查：这两类页面目前没有招生开放数量、招生截止或申请状态聚合，只呈现档案/城市/学科信息与导航，保留原有静态策略。学校详情因包含实时项目卡片而改为按请求渲染。

## 后续边界

本轮前端审查不把 UI 测试当成官网事实核验。学校招生条件、日期、学费是否真实仍需数据审查分支逐条以官方来源核对。没有发现新的当前来源时，未知与需复核状态保留。公开网站部署不在本分支执行。

## 交叉审查追加：长时间打开的比较页面

后续交叉审查确认：记录尚未到 `reviewAfter` 并不意味着申请截止日期尚未到。如果浏览器长期打开，接口加载时的 `applicationState` 会成为过时快照。现已修复：

- 比较状态由当前中国日历日期、官方开/截止日期和字段可信度重新派生，沿用核心 `getApplicationState` 规则；冲突、不可访问或过期的日期证据不能推导为“开放”。
- 中国午夜自动触发重新渲染并以 `cache: no-store` 重新获取比较数据；隐藏标签页恢复可见时同样更新。这在新请求返回前也会隐藏已经结束的申请入口。
- 授课语言与学制一样通过 `FactValue` 显示，记录复核到期后不会从浏览器旧缓存继续暴露原值。
- 卸载时清除定时器和 `visibilitychange` 监听器，现有请求中止机制保持有效。

追加验证：对比/申请卡片/时效面板三个套件 **31 条测试通过**；包括“截止日期已过但复核日期未过”、三个日期字段的冲突、跨中国午夜、恢复可见、语言过期、无缓存请求以及卸载清理。ESLint 零警告；`tsc --noEmit --incremental false` 通过。
