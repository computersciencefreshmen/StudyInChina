# 自动发现与采集调度升级 — 2026-09-16

## 目标与当前架构

网站数据来自学校官方页面，经采集 Worker 保存原文快照、提取实体和字段候选，再由后续证据门禁生成正式记录与发布请求。本次打通“发现链接 → 登记采集源 → 定时入队”这一段，减少维护人员逐条添加来源的工作。注册来源只表示允许采集，不能证明页面内容正确、适用于该校或仍在有效期内。

原先目录解析已经写入 `source_discoveries`，但没有运行时自动填写 `registered_source_id`；`catalog_anchor` 也没有进入实体解析器。只有手工登记的约 10 校 / 100 个精细来源可以持续抓取。这使定时器正常运行也无法扩大实际覆盖范围。

## 本次实施

- 新增 `source-discovery.ts`：从官方快照中的招生、专业目录、奖学金导航发现链接；已有目录实体仍写入候选、实体注册表和目录对账表。导航标签自身不会变成项目事实。
- 定时器每次先自动登记来源，再读取到期任务，新增来源可在同一轮入队。登记来源按学校轮转，避免大型目录占满整批工作。
- 新来源必须有真实快照与父来源外键，学校 ID 必须一致；HTTPS URL 必须属于父来源已批准的具体主机。重定向继续沿用现有校验，不添加通配域名信任，不通过 HTTP 200 或模型猜测认证事实。
- 默认每轮最多登记 20 个来源，可通过 `DISCOVERY_REGISTER_LIMIT` 在 1–100 范围配置；每校自动来源总量上限 100，递归深度上限 2，每页最多 100 条导航发现，默认每 168 小时抓取。新来源仅 HTTP、强制 robots 策略，不继承浏览器选择器和父页面收费、日期等抽取规则。
- 安全不合格、手动禁用、容量受限的发现会隔离或暂缓，7 天后重新检查，其他学校继续运行。去重包含学校 ID 与 URL，不跨学校共享采集实体。
- 预算限制在 SQL 的 `LIMIT` 之前过滤浏览器任务，解决不可执行来源占满批次的问题；配置损坏或单次队列发送失败按来源延后 15 分钟，批次继续处理其他来源，最终以失败心跳报告部分故障。
- 领取任务改为原子检查同源活动任务，防止重叠定时运行和手动请求重复入队。
- 目录解析器升级为 `official-html-v3`，覆盖目录种子、国际招生首页和指南。只有字段与目录两个解析版本都已完成才发送 HTTP 条件请求；避免 304 使目录升级永远被跳过。导航发现写在解析完成标记之前，失败可重试。
- `build-source-import.ts` 保留 `auto-seed-*` 和 `auto-discovery-*` 来源，重新导入历史精细清单不会将运行时新增来源禁用。
- 定时执行接入共享 `automation_service_runs` 心跳，反映采集调度成功或部分失败。

## 适用边界与上线条件

- 主代理正在把官方种子覆盖扩至 272 校，报告时计划包含 1,395 条关联官方 URL；以上数量是待初始化来源规模，不能当作已经采集或核实的数量。
- 新来源的通用字段模型只有页面标题及已有确定性目录实体识别。未知费用、截止日期、录取条件不会自动授予 `verified`；仍需适用的字段 schema、官方引文、双次抽取一致及实体映射门禁。一个页面含多个项目时不可猜测其费用属于哪一个项目。
- 中央奖学金或其他跨校共享网站必须避免把全站目录实体归给任一关联学校；种子初始化应将这类来源限定为非递归、非实体识别用途，或采用明确学校归属后才启用的来源规则。
- 自动登记依赖 D1 中已有学校、来源、快照及 0009 发现结构；心跳依赖 0017 迁移。Worker 定时器、队列、R2 和 D1 绑定需实际部署后才会持续运行；dry-run 只验证可构建。
- 采集深度、学校容量、robots 和预算均为运行边界；受限来源仍保留可追踪状态，不能承诺任意学校网站都能无需适配地完整读取。
