# Annual teaching-language tracks and application rounds

Programme IDs and URLs remain stable. An admission cycle can now carry optional `teachingLanguage` (one canonical teaching language) and `applicationRound` (the exact official label). The intake identity is programme + academic year + season + language + round. Old cycles without either optional scope preserve the original identity key and field-proof hash. No migration or inferred relabelling of existing facts is performed.

Annual conditions (`languageRequirements`, `eligibility`, `applicationMaterials`, `applyUrl`) use the same leaf-verification ledger as dates and fees. A missing field remains missing. Chinese and English tracks cannot borrow each other's tests, documents, tuition, application route, dates or round label. For a multilingual programme an unscoped new-cycle proposal is held. Each scoped leaf quote must name the matching language/round or explicitly state that it applies to all languages/rounds. Quotes containing several language scopes are held unless universal applicability is explicit.

The cloud cycle-discovery engine extracts and independently reviews whole document chunks, with exact source snapshot checks, unique parent identity and matching language/round keys. The importer rechecks the scope, source bytes, approved fields and leaf quotations before creating a separate cycle and field receipts. Maintenance patches must echo the existing cycle's language/round. A changed track invalidates the old leaf-proof hash. Multilingual conditions cannot be written to the global programme field as a shortcut.

The JSON public projection exposes only separately current cycle leaves; adding one proof cannot expose its unreviewed siblings. The programme-cycle API returns the language/round and scoped conditions. Programme details show a separate card for each track, year and round, and suppress global language/eligibility/materials when they could mix scopes. A default cycle selector returns no single cycle when several language/round choices exist; callers can select an explicit scope with the optional fourth argument. Single-track legacy selection remains compatible. Reference tuition keeps its existing qualification.

This local implementation does not call MiniMax, change any historical paid reservation, reset STOP/unknown outcomes, change source data, deploy services or modify D1 storage. All producer requests still use the existing guarded model client. Scope-v1 target exports preserve their historical bytes; scope-v2 target identities supply known parent teaching languages for ambiguity checking.

Validation: `tests/unit/maintenance-language-tracks.test.tsx` covers separate English/Chinese tracks and rounds, cross-language rejection, duplicate/conflicting field output, two independent mocked model passes, import, API and rendered applicant cards, plus track-changed proof rejection. Existing cycle/field verification suites cover legacy compatibility and unchanged evidence windows.
