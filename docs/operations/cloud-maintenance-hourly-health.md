# Hourly cloud maintenance observations

The existing `Automation runtime health` workflow retains its hourly `41 * * * *` schedule and `automation-health-<run-id>` artifact. With `CATALOG_MAINTENANCE_MODE=cloud` it uses the existing maintenance URL/token for one authenticated `GET /status` and independently reads the public release. The legacy branch and its checks remain unchanged for other modes. The public delivery backend is observed independently; a D1 operational database does not make the website D1-backed. Valid JSON, shadow or D1 delivery is accepted unless the caller explicitly supplies an expected backend.

A current durable tick demonstrates scheduler activity, not newly verified data. The report records the configured cohort, actual control/scope bindings, coverage bands, distinct current programme identities, scholarship associations, schools with current scholarships and independently observed public/raw counts. Ready status may select one existing authenticated R2 coverage artifact, whose checksum, catalogue, scope and China date must match. Missing coverage is `unobserved` with null counts. A fresh daily quota wait records its reset time and is a normal waiting state; null controls and false top-level enable flags during quota do not establish a manual pause. No `/schools` or coverage query is made during that wait.

Authentication/configuration errors, unavailable backends, invalid evidence, stale/error ticks and expired reset times remain failures. Existing aggregate unknown outcomes are reported without replay and without pretending each historical protected attempt is a new failure. A current error tick indicating unknown outcome is actionable. An explicitly observed manual pause remains a wait. Processor progress is `unobserved`: the current status endpoint exposes job creation dates and generic scheduler events, which cannot prove when an individual worker last advanced. The health adapter does not invent a processing-stall determination from them or modify the Worker.

The hourly workflow automatically retrieves a prior completed hourly health artifact when one is available and passes it as `--previous <existing-report.json>` for evidence/publication deltas. Continuous quota wait exceeding 24 hours is actionable only when the previous observation is at most two hours old and its recorded wait start does not follow that observation; gaps restart the observation window. The workflow does not invent a previous observation or create a new state ledger. When a previous artifact is unavailable, deltas remain unavailable; expired reset and stale-tick checks still run. Positive observed growth sets the report's `notification.growthDetected` and `notification.changed` fields without adding a notifier or outbound message. A reset wait is not a completed upgrade or published growth. Latest publication acknowledgements remain explicitly unobserved when the status contract does not expose them.

The adapter has no model API calls, quota polling, writes to the service, recovery, dispatch, billing changes or reservation resets. It only writes its requested local JSON report. Use `node --import tsx scripts/automation/cloud-maintenance-health.ts --output <artifact.json>`; fail/unobserved readiness exits nonzero, while an honestly recorded operational wait exits zero. The report retains unknown fields and does not claim production work completed.
