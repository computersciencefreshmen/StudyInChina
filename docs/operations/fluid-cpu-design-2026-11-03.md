# Fluid Active CPU 优化：设计与证据边界

## 目标与现场

StudyInChina 将官方资料、身份审查台账和字段核验投影为多语言公共目录。真正需要减少的是相同证据被独立请求反复处理的计算，同时保留来源、身份范围、receipt 完整性、字段资格和到期判断。本轮不增加付费设施；实现、服务恢复、生产计量验证是三个独立事项。

本地原工作区停在较旧的 `87751c9`，且有大量未提交工作。本轮在 `codex/fluid-cpu-cache` 独立工作树上基于现场确认的默认分支 `c93a6cad17df5fc006e9fef69976cd4e5d08e79a` 实施，未覆盖原工作区。该 SHA 的历史 Vercel 部署和生产别名提升记录成功，但当前稳定域名的一次只读请求返回 `402 / DEPLOYMENT_DISABLED`。详情见[部署审计](fluid-cpu-deployment-audit-2026-11-03.md)。暂停原因和用量数字来自用户提供的控制台观察，本轮没有账号侧计量权限来独立重算。

## 调整后的数据流

```text
部署文件/本地数据文件
  → 文件依赖检查 → schema 严格解析后的原始快照
  → 身份台账 + strict receipt 校验快照、字段台账快照
  → 按原始快照身份 + 证据快照身份 + 上海业务日期选择公共快照
       ├─ current：现行资格/事实
       ├─ directory：可公开身份与独立当前字段
       ├─ directory revision
       └─ 原始 release 元数据
  → 每次请求的筛选、分页、语言显示、HTML/API 序列化
```

`file-snapshot.ts` 的有界实例缓存记录真实路径、设备/inode、大小和纳秒 mtime/ctime；通过 `realpathSync.native` 检查真实路径，保留符号链接目标变化检测，避免用 JavaScript 对每个 receipt 逐层遍历父目录。缺失文件也记录为依赖，创建后会失效。命中时检查元数据，不为寻找缓存键重新序列化或哈希整个目录。原有 receipt 内容哈希与范围核验仍在初始化/证据变更时执行。

原始数据、身份台账、receipt 或字段台账改变，相关快照会重建；读取过程中依赖变化会重试，连续变化则失败，避免发布读取期间发生变化的一代结果。strict 身份台账的失败向上传递，旧公开结果不会用来绕过失败；修复后下一次读取可重试。旧版无范围 receipt 的兼容规则保留，缺失受范围约束的 receipt 仍拒绝。字段台账异常仍沿用原有保守行为，不授予相应独立字段资格。

快照递归冻结，调用方无法修改共享数组或嵌套对象污染后续请求。同步文件初始化在一个 JavaScript isolate 中不可交错；原有异步自定义 loader 的 Promise 共享与失败后清除机制保留。公共投影按不可变对象身份复用，日期使用固定 `Asia/Shanghai`；跨日替换该 bundle 最新保留的公共结果，到期记录及字段重新判定。revision 的完整哈希仅在公共快照失效时计算。

JSON runtime 的 bundle 与 release 现在由同一原始快照产生，避免分别读取时元数据和计数属于不同代。`getRelease` 的原始数据日期/计数语义保留。D1、shadow 的远端数据更新契约不引入这套本地投影缓存。预览 raw 数据在公共投影前分支；认证管理端和个人通知响应保留 private/no-store，公共缓存键不包含用户身份或认证结果。

这是一种性能与时效性的明确取舍：每次仍付少量文件元数据检查成本，换取变更及时失效；首次初始化仍要严格解析、校验、投影、冻结。每个函数实例/冷启动各自初始化，实例之间不共享结果。Vercel 部署文件不可变；本地或管理执行器落盘更新通过文件依赖失效，新部署自然使用新的独立实例。

## 响应层与验证边界

本轮保留动态公共 HTML。数据缓存降低函数内部 CPU，但 HTML 仍可能触发服务器函数；没有将其报告为 CDN 节省。现有公开 API 策略继续将浏览器和共享缓存及 stale 窗口限制在上海午夜前，并新增 payload `evaluatedForDate` 保护：跨午夜才完成、缺少有效日期或日期不匹配的响应使用 `no-store`。恢复后仍需读取实际 Vercel 响应和缓存命中，才能证实 CDN 行为。

线上 smoke 默认集中核对变更对象、关联大学和必要哨兵，保留变更事实、全部公共语言、浏览器导航、移动布局及过期对象检查；全站枚举保留为本地/CI 默认和显式远端 full 模式。通过 `changed` 的 proof 明示覆盖范围，不宣称验证全站 ID 集合。实际减少的请求和 CPU 仍取决于操作者执行频率。

证据与测试入口：

- `tests/unit/file-snapshot.test.ts`：原子替换、同大小变更、缺失依赖创建、初始化失败恢复、读取中变更与嵌套冻结。
- `tests/unit/public-snapshot-cache.test.ts`：并发初始化、数据/receipt/台账更新、上海日期与字段到期、多语言名称范围、预览/认证与公共结果隔离。
- `tests/unit/catalog-response-cache-boundary.test.ts`、`backend-trust-boundaries.test.ts`：午夜响应和公共/预览部署边界。
- `tests/unit/catalog-api-service.test.ts`、`verified-program-name.test.ts` 及 release smoke 测试：分页投影和严格来源/名称语义。
- [原始验证与基准证据目录](fluid-cpu-evidence/)；最终通过范围、测量值和限制由本轮结果报告统一记录。

计算基线在全部缓存/索引改动前采集。首次本地生产构建基线仅提前包含午夜响应头正确性修复；普通日间请求策略不变，不能将该基线误称为完全未经任何改动的构建。对比使用同数据、日期、请求集和运行条件；CPU 由进程 CPU 时间统计，墙钟时间另记。同进程热调用只能证明实例内复用，不能证明冷启动、跨实例或 CDN 收益。暂停站点的失败请求或零用量不参与改善判断。

## 预算模型与恢复后的观察

团队目标约 5–6 分钟 CPU/天。用户提供的近期约 40 分钟/天若持续，是约 20 小时/30 天的量级；免费额度平均 8 分钟/天，留 30% 余量后约 5.6 分钟/天。评估目标因此接近 86% 总 CPU 降幅，不能用历史累计只超约 15% 代替。

按路由计算，单位统一为 CPU 秒：

```text
每日团队 CPU = 其他项目 CPU + proxy 等独立开销
             + Σ 路由请求数 × (1 - CDN 有效命中率)
                 × [(1 - 冷请求比例) × 热请求 CPU + 冷请求比例 × 首次请求 CPU]
30 天 CPU = 30 × 每日团队 CPU
```

首次请求 CPU 包含该请求承担的初始化；异步等待不作为 CPU。请求数应包含真实访问、机器人、预取和发布验证；避免又单列验证流量而重复计数。CDN 前仍执行的 proxy 要独立计算。恢复后的最低观察集是按路由的请求数/CPU、冷启动和实例数、CDN HIT/MISS、错误率、机器人特征、发布 smoke 次数，以及上海午夜前后资格与响应日期。没有这些权重，不承诺团队能稳定达标；可以用保守的低命中/高冷启动情景判断余量。

## 风险与回滚

主要剩余风险是冷启动仍有初始化成本、实例内存增加、热点请求可能受筛选/渲染剩余成本支配，以及实际 CDN 和流量构成未知。多文件本地发布仍应先完成校验再原子替换或通过新部署发布；缓存不能把跨文件写入变成数据库事务。

如出现异常，在本轮独立分支上撤销本轮缓存/索引/分页和 smoke 范围改动，重建并重启实例；部署后通过原有受控发布流程回退代码即可清空实例缓存。保留严格数据及 receipt，不回滚真实数据、不删除身份检查，也不改账号套餐。运行时没有新增持久化缓存需要迁移。回滚构建同样执行类型、数据与关键正确性检查。

优化不会清除累计用量，也不会解除 Vercel 暂停。本轮未执行套餐升级、付费、账号恢复或新的生产部署；恢复必须按既有授权和账号状态另行处理，恢复后的计量才能用于线上成效结论。
