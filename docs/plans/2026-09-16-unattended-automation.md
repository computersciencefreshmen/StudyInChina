# 无人值守更新与核验设计

日期：2026-09-16。用户要求持续发现、核对、更新学校及项目，无须逐条人工操作。

## 架构

已有官方目录 → 受信主机种子 → Cloudflare 定时抓取 → R2 原始快照 → 确定性规则/双次模型一致性及引用核验 → 实体规范化/字段发布 → 完整版本 → 网站。

- Cloudflare Worker 是托管运行的程序，即使本机关闭也能定时执行；保留现有 D1、队列和 R2，避免重新引入工作流平台。
- D1 存储调度状态、证据索引和规范化数据；R2 保存不可变原始快照；队列控制并发与重试。
- 自动发现只扩大已知官方主机内的采集目标，不授予事实“已核验”状态。全校种子来自已有学校记录及其明确关联的 official 来源，不根据搜索排名或域名后缀猜测。
- 每个新来源有深度、学校总量及每轮预算限制，遵守 robots 和请求间隔。
- 暂时的数据库/网络故障可自动退避和重试；证据冲突不以基础设施失败方式重试至通过，保留隔离并等待新快照或解析器修正。
- 持久服务心跳分开记录开始、成功、错误，防止 /health=200 掩盖调度停跑。

## 网站交付

线上历史版本使用 JSON，旧 D1 内容不足，不能直接切换。加入兼容快照完整性门禁：比较每个已有学校、项目等稳定身份，不仅总数；拒绝核验时间倒退、缺少关联来源或不合法结构。未通过时继续保留现有网站并报告缺口，云端继续采集。

每日维护可自动降级超期记录；不会仅因时间过去重写核验日期。程序抓取的候选结果继续走证据发布链路。

## 运行与部署

- 根代理负责全校种子、持久心跳公共组件、CI/计划接线、跨后端交付和实际运行检查。
- 发现代理负责自动注册、采集公平性、内容未变时的解析器重跑。
- 发布代理负责物化/发布重试、租约、版本完整性和日常版本生成。
- 运维代理负责只读真实运行检查、异常去重和持续跟进。

上线前必须通过迁移、Worker 单元回归、类型检查与 dry-run。实际激活状态以远端版本、触发器和持久心跳证据为准。缺失外部凭据明确记录，不以绿色空跑代替成功。
